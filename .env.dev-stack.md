# Dev Stack Startup

## Usage

```powershell
# Windows mode (default) - runs API and web on Windows
.\start-dev.ps1

# WSL mode - runs API and web inside WSL via wsl.exe
.\start-dev.ps1 -RunEnv wsl

# WSL mode with custom ports
.\start-dev.ps1 -RunEnv wsl -ApiPort 8100 -WebPort 3100

# Stop the running stack (auto-detects which env was used)
.\start-dev.ps1 -Action stop

# Check status
.\start-dev.ps1 -Action status
```

Or via the CMD wrapper:

```cmd
start-dev.cmd -RunEnv wsl
```

## What `--RunEnv wsl` does differently

1. **Path conversion**: Converts `CODEX_HOME`, `CODEX_WORKSPACE_*`, and `CODEX_WORKTREE_ROOT` in `api/.env` from Windows paths (e.g. `C:\Users\KSG\.codex`) to WSL paths (e.g. `/mnt/c/Users/KSG/.codex`).
2. **Process launch**: Starts `python3 -m uvicorn` and `npm run dev` inside WSL via `wsl.exe bash -lc`, instead of Windows `python.exe` / `npm.cmd`.
3. **Path restore on switch back**: When you run with `-RunEnv win` after a WSL session, any WSL paths (`/mnt/...`) in `api/.env` are automatically converted back to Windows paths.

## Prerequisites for WSL mode

- Python 3 and the API dependencies (`uvicorn`, `fastapi`, etc.) must be installed inside WSL.
- Node.js / npm must be available inside WSL.
- `codex` binary must be on PATH inside WSL (or set `CODEX_BIN` to its absolute WSL path).

## WSL2 localhost forwarding

WSL2 forwards `127.0.0.1` to Windows automatically, so the API and web ports are reachable from Windows browsers and the desktop pet without extra configuration.
