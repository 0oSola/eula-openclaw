# 科技感个人助手界面功能列表

## 1. 文档目的

本文用于辅助 `/companion` 页面重新设计。目标是把当前偏调试面板的界面，改造成一个更有科技感、更像个人助手的交互界面。

参考原型：

- Pencil 画布名称：`Cyber Assistant Cockpit UI`
- Pencil 节点 ID：`p67op`
- 原型方向：深色 AI 控制台、中央 MMD 助手、左右信息面板、底部指令输入栏

本文不描述具体代码实现，而是列出设计需要覆盖的功能、页面信息和交互状态。

## 2. 总体产品定位

这是一个“虚拟个人助手控制台”，不是普通聊天窗口，也不是后台管理页面。

用户进入页面后，应该感受到：

1. 中央的 MMD 角色就是当前正在工作的助手。
2. 用户可以直接通过底部输入框下达任务。
3. 助手会理解上下文，并通过表情、动作、语音和文字回应。
4. 页面能展示助手当前状态、任务进度、记忆摘要和调试 trace。
5. 高级配置存在，但不会干扰主要聊天体验。

## 3. 页面区域总览

```text

+-- 退出登录

主控制台
+-- 左侧状态面板
|   +-- 当前上下文
|   +-- 能力状态
|   +-- 快捷模式

+-- 语音模式
+-- 高级功能入口
```

## 4. 功能清单

### 4.1 顶部状态栏

用途：告诉用户当前正在和哪个助手交互，以及系统是否可用。

需要展示：

- 助手名称，例如 `MIO // PERSONAL AI`。
- 助手在线状态，例如 `LIVE`。
- 记忆或上下文状态，例如 `MEMORY SYNCED`。
- 当前用户 ID。
- Trace 页面入口。
- 退出登录按钮。

设计要点：

- 视觉上像 HUD 状态栏。
- 不要做成普通网站导航。
- 文案可以使用等宽字体，强化科技感。
- 在线状态建议使用发光小圆点。

现有数据来源：

- `session.userId`
- `loadSession()`
- `/traces` 页面链接
- `clearSession()`

### 4.2 中央 MMD 助手舞台

用途：作为整个页面的视觉中心，承载“个人助手存在感”。

需要展示：

- 当前 MMD 模型。
- 模型名称。
- 模型选择器。
- 当前情绪，例如 `neutral`、`happy`、`thinking`。
- 当前动作，例如 `idle`、`wave`、`comfort`。
- 是否正在说话。
- 模型加载状态。
- 模型加载错误。

设计要点：

- 中央区域必须是页面视觉权重最高的部分。
- MMD 角色不能像一个小预览窗口，而应该像助手核心。
- 舞台背景可以使用环形光圈、扫描线、网格、能量环等科技感元素。
- 模型选择器可以放在舞台角落，不要抢主要视觉。

现有数据来源：

- `MMDStage`
- `models`
- `selectedModelPath`
- `selectedModel`
- `modelLabel`
- `interaction.emotion`
- `interaction.action`
- `interaction.mode`
- `speaking`

### 4.3 底部指令栏

用途：用户最主要的操作入口。

需要支持：

- 输入消息。
- 发送消息。
- 显示发送中状态。
- 禁止重复发送。
- TTS 开关。
- TTS 模式选择：`browser` / `server`。
- 显示错误信息。

设计要点：

- 底部输入框要比普通聊天输入框更像“命令中心”。
- 可以使用浅色输入栏放在深色背景上，形成强对比。
- 发送按钮要明显。
- 输入提示语建议使用：
  - `让 Mio 帮你计划、记住、渲染或执行...`
  - `输入你想让助手完成的事...`
  - `Ask Mio to plan, remember, render, or act...`

现有数据来源：

- `input`
- `setInput`
- `onSubmit`
- `loading`
- `error`
- `ttsEnabled`
- `ttsMode`
- `setTtsEnabled`
- `setTtsMode`

### 4.4 对话历史

用途：保留用户和助手的上下文，不让页面只像一个单次命令工具。

需要展示：

- 用户消息。
- 助手消息。
- 系统消息。
- 每次助手回复的 `trace_id`。
- 错误消息。

设计要点：

- 对话历史不应该占据页面主视觉。
- 可以放在右侧面板、下方抽屉或可折叠区域。
- 默认只显示最近几条，避免界面变成传统聊天页。
- `trace_id` 应该是次要信息，使用小号等宽字体。

现有数据来源：

- `messages`
- `ChatMessage.role`
- `ChatMessage.content`
- `ChatMessage.traceId`
- `error`

### 4.5 左侧状态面板

用途：展示助手当前处于什么工作状态，增强“系统正在运行”的感觉。

建议模块：

1. 当前上下文
   - 当前用户正在进行的主题。
   - 例如：`项目界面重设计`、`MMD 模型调试`。

2. 能力状态
   - 记忆能力。
   - 语音能力。
   - MMD 舞台能力。
   - Trace 调试能力。

3. 快捷模式
   - 专注陪伴模式。
   - 动漫回应模式。
   - 任务执行模式。

设计要点：

- 左侧面板用于增加科技感和系统感。
- 不需要一开始全部可交互，可以先作为状态展示。
- 使用进度条、状态胶囊、发光标签等视觉形式。

可能的数据来源：

- `session.userId`
- `ttsEnabled`
- `ttsMode`
- `models.length`
- `selectedModel`
- `messages`
- `interaction.mode`

### 4.6 右侧任务面板

用途：展示助手“理解了什么”和“接下来要做什么”。

建议模块：

1. 下一步建议
   - 根据当前输入或最近对话显示下一步任务。
   - 初期可以用静态文案或基于最近消息简单生成。

2. 记忆摘要
   - 展示助手记住的用户偏好。
   - 例如：`用户偏好科技感界面`、`用户希望界面不像后台`。

3. Trace 状态
   - 显示最近一次请求状态。
   - 显示最近一次 `trace_id`。
   - 提供跳转 Trace 页面入口。

4. 回复元数据
   - 当前情绪。
   - 当前动作。
   - 是否降级。
   - 使用的 endpoint。

设计要点：

- 右侧面板要让用户感觉助手有上下文和执行意识。
- 不要把所有 debug 字段直接堆出来。
- 高级 trace 信息可以二级展开。

现有数据来源：

- `messages`
- `response.trace_id`
- `response.emotion`
- `response.action`
- `response.endpoint_used`
- `response.degraded`
- `/traces`

### 4.7 模型切换

用途：允许用户选择不同 MMD 模型。

需要支持：

- 列出可用模型。
- 显示模型名称。
- 切换当前模型。
- 无模型时显示空状态。
- 模型加载失败时显示错误。

设计要点：

- 模型切换是重要功能，但不是主要操作。
- 建议放在中央舞台的设置角落，或者放进“舞台设置”折叠面板。
- 当前模型名称应该可见。

现有数据来源：

- `listMmdModels()`
- `models`
- `selectedModelPath`
- `setSelectedModelPath`
- `getModelDisplayLabel()`

### 4.8 语音与 TTS

用途：让助手更像个人陪伴，而不仅是文字回复。

需要支持：

- 开启 / 关闭 TTS。
- 切换浏览器 TTS 和服务端 TTS。
- 显示说话中状态。
- 服务端 TTS 不可用时回退浏览器 TTS。

设计要点：

- TTS 不要放成普通表单控件。
- 可以设计成语音模式胶囊、HUD 开关或小型状态按钮。
- 说话中状态应该反馈到中央 MMD 舞台。

现有数据来源：

- `ttsEnabled`
- `ttsMode`
- `speaking`
- `browserSpeak()`
- `requestServerTts()`

### 4.9 VMD 与动作映射

用途：让助手的情绪和动作可以绑定到 VMD 或程序化动作。

需要支持：

- 查看当前映射。
- 上传 / 管理 VMD 资源。
- 预览 VMD 动作。
- 将情绪槽位映射到动作。
- 支持程序化动作和 VMD 动作两种模式。

设计要点：

- 这是高级功能，不应该默认占据主页面。
- 建议放入：
  - 高级设置抽屉；
  - 舞台设置面板；
  - 单独的 `Advanced` 区域；
  - 或未来拆成独立路由。

现有数据来源：

- `MappingEditor`
- `mappings`
- `assets`
- `setMappings`
- `setAssets`
- `previewVmdAsset`
- `resolvePlaybackPlan()`

### 4.10 Trace 与调试

用途：给开发和排障保留可追踪能力，但不破坏助手产品感。

需要支持：

- 当前消息关联的 `trace_id`。
- 跳转 Trace 页面。
- 显示最近一次请求状态。
- 显示错误原因。

设计要点：

- Trace 是次要功能。
- 默认只显示摘要。
- 完整信息应该跳转到 `/traces`。

现有数据来源：

- `response.trace_id`
- `messages[].traceId`
- `Link href="/traces"`
- `error`

### 4.11 会话与登录

用途：保证用户身份和上下文明确。

需要支持：

- 未登录状态提示。
- 返回登录页。
- 当前用户 ID 展示。
- 退出登录。

设计要点：

- 未登录页面也应该保持同一套科技感视觉。
- 不要继续使用普通卡片式提示。

现有数据来源：

- `loadSession()`
- `clearSession()`
- `router.push("/")`
- `session.userId`

## 5. 原型图区域说明

### 5.1 顶部 HUD 状态栏

原型中的顶部状态栏是一个细长的科技感信息条。它不是传统导航，而是系统状态展示。

它应该表达：

- 当前助手已上线。
- 当前会话已连接。
- 记忆和语音模块处于可用状态。
- 用户可以快速进入 Trace 或退出。

### 5.2 中央助手核心

原型中的中央区域是整个页面最重要的区域。MMD 角色位于圆环和光效中心，像一个正在运行的 AI 核心。

它应该表达：

- 助手有实体感。
- 当前状态正在实时变化。
- 文字回复、语音和动作都与这个角色关联。

### 5.3 左侧系统状态

原型左侧更像飞船或 AI 控制台的遥测信息。

它应该表达：

- 助手当前知道什么。
- 当前能力是否可用。
- 用户可以快速切换工作模式。

### 5.4 右侧任务与记忆

原型右侧用于体现助手不是单纯聊天，而是知道用户目标。

它应该表达：

- 当前下一步是什么。
- 助手记住了什么用户偏好。
- 最近一次请求是否正常。

### 5.5 底部指令栏

原型底部是最重要的交互入口。

它应该表达：

- 用户只需要说出要做什么。
- 助手会负责执行、记住、回应和驱动 MMD 动作。

## 6. 功能优先级

### P0：必须保留

- 聊天发送与回复。
- MMD 舞台显示。
- 情绪和动作驱动。
- TTS 开关与模式选择。
- 模型切换。
- 错误提示。
- Trace ID 保留。
- 退出登录。

### P1：首版重设计建议实现

- 顶部 HUD 状态栏。
- 中央助手核心视觉。
- 底部大指令栏。
- 左侧状态面板。
- 右侧任务 / 记忆摘要。
- MappingEditor 折叠到高级区域。
- 响应式布局。

### P2：后续增强

- 快捷模式真正影响 prompt 或交互行为。
- 自动生成记忆摘要。
- 全屏舞台模式。
- 语音输入。
- 助手状态动画。
- Trace 摘要自动诊断。
- 多助手人格切换。

## 7. 空状态与异常状态

### 未登录

显示：

- 助手离线状态。
- 返回登录页按钮。
- 简短说明：需要先输入用户 ID。

### 无 MMD 模型

显示：

- 中央舞台空状态。
- 文案：`未发现可用 MMD 模型`。
- 提示检查 `MMD/` 目录。

### 模型加载失败

显示：

- 错误信息。
- 当前模型名称。
- 重试或切换模型入口。

### Chat API 失败

显示：

- 指令栏附近出现错误提示。
- 右侧 Trace 区显示失败状态。
- MMD 助手切换到 `caring` / `comfort` 状态。

### TTS 不可用

显示：

- 服务端 TTS 不可用时提示回退浏览器 TTS。
- 不阻塞文本回复。

## 8. 设计验收标准

1. 第一眼能看出这是一个科技感个人助手界面。
2. 中央 MMD 助手是视觉主角。
3. 用户能立刻知道在哪里输入指令。
4. 页面不像后台管理系统。
5. 高级配置不干扰主要对话流程。
6. 所有现有核心功能都能找到入口。
7. 错误、加载、空状态都有明确反馈。
8. 桌面端在 `1440x900` 下布局完整。
9. 移动端不出现横向滚动。
10. 中文文案不乱码、不截断。
